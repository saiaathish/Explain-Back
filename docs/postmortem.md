# Postmortem: five hardening decisions that mattered

Explain-Back’s hardest failures were not spectacular model failures. They were boundary failures: text that looked identical to a person but was not identical to the matcher, a similarity calculation that quietly changed meaning when a justification was added, an upstream 429 reported as malformed JSON, and inputs large enough to kill the process before application code could reject them. The final architectural decision was similarly about boundaries: keeping every model-backed path behind one provider egress rather than adding a browser speech vendor.

The first incident appeared when users pasted text copied from PDFs. A source passage could contain hard line breaks or tabs inside a sentence, while the model returned the same words with ordinary spaces. The original exact locator treated those as different strings and silently dropped the concept, proposition, or justification span. The visible result was an apparently incomplete analysis: the system had produced a concept, but the renderer had nothing valid to color. The fix landed in `6321ff4` and was merged as `f51c69b`. `backend/extract.py` now collapses whitespace for matching, maps the flattened match back to offsets in the original text, and stores the raw original slice. Tests cover hard wraps, tabs, repeated spaces, cursor movement, raw re-slicing, and fabricated-span rejection. This was the correct fix because it repaired representation noise while preserving the verbatim-or-discard invariant: the UI still displays text from the learner’s actual input, not a normalized reconstruction. A broader fuzzy matcher was rejected because it would make fabricated or near-miss spans look valid and would weaken the evidence boundary.

The second incident was found while investigating why revisions did not reliably report “gaps closed.” `align()` currently embeds `claim_span + justification_spans` together, although the blueprint and calibration pairs specify claim-only vectors. That joined representation creates semantic drift: a correct because-clause can pull the vector away from its concept, lower cosine similarity, and push a claim toward grey. The tempting fix was one line—embed only the claim—but the measured experiment showed why judgment mattered. Joined behavior scored 34/37 on the original set and 45/55 on the expanded set; claim-only scored 31/37 and 43/55, failing the existing release floor. Both runs were deterministic. The golden baseline and thresholds had been calibrated around the drifted runtime, so changing alignment alone would have changed the meaning of the gate. The fix was deliberately not shipped. `18d49f9`, `backend/align.py`, and `docs/revise-loop.md` record that this requires coordinated recalibration, alignment changes, and expectation updates. Leaving a known defect documented was safer than making a “clean” change that silently invalidated the release evidence.

The third failure was operational rather than semantic. Provider rate limits were being retried through the parse-failure path, so an HTTP 429 could surface to the browser as “model output unparseable,” a 502-shaped message that sent debugging in the wrong direction. Commit `cb92105` introduced a distinct `LLMRateLimitError`, parses numeric `Retry-After` values, uses the provider window or a bounded fallback, and re-raises rate-limit errors after retries. `backend/main.py` maps those errors to HTTP 429 while malformed model output remains a visible 502. Tests cover numeric, missing, and malformed `Retry-After` headers and assert that a 429 is never converted into a parse error. This separation was correct because throttling is a capacity signal, not evidence that the model emitted invalid JSON. Increasing parse retries would only amplify provider pressure and obscure the real condition.

The upload incident was found during production voice/image hardening. An oversized base64 request could cause Render or the server process to fail while the web framework was still parsing the body, so FastAPI’s ordinary validation never got an opportunity to return a controlled response. Commit `4e812db` added endpoint-specific decoded limits, envelope limits for base64 requests, and middleware that rejects a declared `Content-Length` above the cap before body parsing, returning JSON 413. Post-parse guards remain as a second line of defense for decoded image and audio data. The verified repository evidence supports one documented oversized-upload production incident and this fix; the overnight brief’s claim of three separate outages could not be independently confirmed in git history or local notes, so this postmortem does not invent two additional narratives. The tempting alternative—validating only inside the route—was inadequate because the demonstrated failure happened before route validation. The middleware fix protects the process boundary while retaining precise decoded-size errors.

The final decision concerned voice input. The browser Web Speech API was attractive because it appeared to avoid a backend endpoint, but it introduced a second vendor egress path and was unreliable for technical terms. The same `cb92105` change replaced it with local `MediaRecorder` capture. `frontend/src/voice.js` handles recording and cleanup; `frontend/src/App.jsx` caps recordings at three minutes, converts the blob to a data URL, sends it to `/api/transcribe`, and appends the editable transcript. `backend/llm.py` sends the audio part through the configured provider boundary. This preserved the single-egress invariant enforced by the backend tests and, importantly, kept transcription reviewable before analysis. A browser-only speech path would have been shorter code, but it would have violated the project’s privacy and provider-boundary decision while making technical vocabulary depend on browser-specific speech engines.

Across these incidents, the recurring lesson is that reliability came from preserving distinctions: whitespace variation versus textual fabrication, justification versus claim meaning, throttling versus malformed output, request envelope size versus decoded content, and local capture versus external model egress. The fixes that shipped are narrow because they address the observed boundary. The issues intentionally left open—especially alignment drift and the unverified outage count—remain explicit rather than being hidden behind a cleaner story.
