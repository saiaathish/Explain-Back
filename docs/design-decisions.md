# Design decisions

## Why these similarity thresholds

The system has to decide whether a student's claim is close enough to a concept in the source material. We did not choose the cutoffs at random or copy a number from a research paper. Different embedding models can place the same pair of sentences at different distances, so a borrowed number would not necessarily transfer to this system. Instead, we hand-labeled 20 real example pairs from this project as clearly matching, partially matching, or not matching. We measured the similarity values for those labeled pairs and chose the cutoffs where the actual groups separated in the observed data. The high-similarity threshold is `T_HIGH = 0.732`; the lower threshold is `T_LOW = 0.680`. Claims above the high cutoff can support a strong match, claims between the cutoffs are treated more cautiously, and claims below the lower cutoff are not treated as close enough. This means the thresholds are backed by an actual measurement on this specific system, not a borrowed number that might not apply.

## Why there is a fourth grey state

A misconception detector usually has an uncomfortable choice: say nothing, or accuse a student of making an error. Research on this exact kind of detection found that even a strong AI model can produce roughly eight false alarms for every one real, correct catch when misconceptions are rare in ordinary student writing. Being wrongly told that you have a misconception is worse for learning than the system admitting it is unsure. Explain-Back therefore has a fourth state, grey: “not sure.” It avoids forcing every sentence into right or wrong. The code is deliberately stricter before showing red. A red flag is shown only when the system is highly confident and the sentence is specific—for example, it contains a number, a direction word, or an absolute word such as “always” or “never.” Vague or hedged sentences do not become red accusations; they fall back to grey instead. The result is quieter feedback that is more honest about uncertainty.
